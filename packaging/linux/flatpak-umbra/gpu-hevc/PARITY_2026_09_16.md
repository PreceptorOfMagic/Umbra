## Candidate changes

- Keep original luma on the GPU to propose sparse wider motion candidates. Rank complete blocks and refine motion against the reconstructed reference that HEVC prediction actually uses. Using the original reference for the entire search helped noisy texture but degraded the varied scene; combining original proposals with reconstructed ranking retains both gains.
- Replace texture-suppressing activity allocation with a balanced rotating mix of neighboring integer CU QPs, implementing quarter-step quality.
- Learn bit-size sensitivity from same-picture retries already performed by the feedback controller. Symmetric bounded bitrate credit changes the next target without a frame queue, waiting or an access-unit cap. At most three attempts remain.
- Apply normative GPU deblocking, including inherited QP on zero-residual CUs, chroma mapping, 8/10-bit scaling and intra boundary strength. Filtering across slices stays disabled.
- Allow DC intra inside P pictures using immutable reconstructed neighbors. Three positions of a rotating 2×2 grid reconstruct first; the eligible position chooses inter/intra and reconstructs once. Retries rebuild neighbors at their new QP.
- Match Apollo's P010 conversion order: normalized legacy color vectors, 16-bit UNORM rounding, then high ten-bit extraction. On the measured HDR pan source, luma conversion MSE fell from 3.64 to 0.000638 code-value squared; maximum discrepancy fell from 3 to1.

All production picture work remains GPU-side. CPU x265 supplies headers and motion-cost tables. The exported ABI and Apollo packetizer remain unchanged. The syntax profile retains CTU32/minCU16, one slice/reference, no B pictures, temporal MVP, WPP, weighted prediction or SAO.

## Measured image quality

Fresh offscreen D3D textures feed each encoder. The NVENC reference compiles the actual unchanged Apollo owner sources and shaders. Tests use 3840×1088 at a nominal 165fps and 38988kbps, 180 frames, with explicit IDRs at 0 and 9. Submission is not paced; elapsed 1/165 is supplied to the beta component controller. Source readback happens after timed encoding and cannot feed the encoder. These are component comparisons, not a live stream or gaming-load verdict.

Installed v9 produced SDR texture MSE 764.16 over the same 180-frame fixture; this candidate produces 413.44. The varied holdout scene contains multiscale texture, tile boundaries, an independently moving object and stationary HUD marks. It was added before tuning the current profile. Its measured gap closed when reconstructed references ranked the source-derived motion candidates. Inspected luma crops show similar retained structure in v10 and NVENC; both soften fine grain relative to the original. Dense changing texture, scene-change recovery and gaming-load latency remain acceptance questions.

Measured NVIDIA predicted-picture submission medians are about 4.7–5.3ms for the optimized candidate, versus about 2.9–3.0ms for the SDR native NVENC reference. AMD component medians in the final checks span 10.2–11.7ms. These timings include offscreen drawing, GPU color conversion and encoding, and exclude real desktop capture and source readback and do not measure performance while a game competes for the GPU. The earlier installed-v9 AMD medians were roughly 8.2ms in separate runs, so the quality gain has a material encode-cost increase.

## Compatibility evidence

Independent FFmpeg decoding reproduces GPU reconstruction exactly for all tested candidate pictures. Final v10 qualification passed on NVIDIA RTX 4070 and AMD RX Vega. All four input formats, both DLL depths and mixed horizontal 8-bit composition passed before installation; the remaining mixed layouts/depths and complete cadence suite passed after the live run:

- 8-bit SDR and 10-bit HDR, row 3840×1088 and column 1920×2176 panes.
- Four mixed-GPU compositions through the unchanged C splicer.
- Both primary roles for each layout/depth, unequal arrival sequences, held panes, isolated IDRs and composite POC wrap. Each cadence case produces 323 composite frames and 614 held panes.
- Both host DLL depths, two concurrent connections, frame-identity and failure handling, with exact decoding on each GPU.

This supports interoperability for those inputs and drivers. It does not establish TV decoder/presentation behavior, other GPUs, game-load latency or subjective visual acceptance. The short TV window covered horizontal SDR presentation only.

The completed v10 run used SKYNET above VEGA, the existing automatic codec selection, native 3840×1088 panes, no frame caps and unchanged bitrate settings. Four advancing TV screenshots were personally inspected at approximately 50, 76, 102 and 128 seconds after launch. The grain strip is intentional pattern content and remains visibly compressed. This is a short visual smoke, not an A/B perceptual score or proof that no transient flash occurred between samples.
